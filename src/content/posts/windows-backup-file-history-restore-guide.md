## 윈도우 백업 파일 기록 차이와 보호 도구의 구분

윈도우 운영체제에서 자료 보존을 계획할 때 흔히 겪는 혼선은 내장된 여러 보호 도구가 서로 같은 역할을 대신할 수 있다고 생각하는 점입니다. 대표적으로 클라우드 기반 설정 동기화 중심의 Windows Backup과 로컬 저장 장치에 파일 판본을 쌓는 파일 기록(File History)은 작동 방식과 저장 장소에서 큰 차이를 보입니다. 여기에 시스템 파일 상태를 되돌리는 시스템 복원과 디스크 고장 뒤 윈도우 재설치에 쓰는 복구 드라이브까지 더해지면 점검 기준을 세우기 어렵습니다.

결론부터 짚으면, Windows Backup은 개인 마이크로소프트 계정(MSA)과 원드라이브(OneDrive)를 통해 바탕 화면, 문서, 사진, 비디오, 음악 폴더와 앱 목록, 시스템 기본 환경설정을 동기화하여 새 PC로 이전할 때 유리합니다. 반면 파일 기록은 외장 드라이브나 네트워크 위치를 지정하여 라이브러리에 포함된 개인 파일의 변경 이력을 지속적으로 기록하므로, 잘못 수정한 파일이나 삭제된 특정 시점의 문서를 복원하는 데 적합합니다. 두 기능은 보존하는 위치와 복원 목적이 전혀 다르므로 필요에 맞춰 병행하거나 선택해야 합니다.

저장 공간을 정리하거나 백업 경로를 점검할 때는 [윈도우 C드라이브 용량 부족, 파일을 잃지 않고 정리하는 순서](/posts/windows-storage-cleanup-safe-order-guide/)를 함께 확인하면 디스크 여유 공간을 관리하는 데 실질적인 기준을 잡을 수 있습니다. 또한 지원 수명 주기를 확인하려는 사용자는 [윈도우 10 지원과 확장 보안 업데이트 안내](/posts/windows-10-esu-2027-extension-guide/) 자료를 참고하여 본인이 사용하는 운영체제의 보안 업데이트 유지 여부를 점검하는 편이 안전합니다.

## 보존 대상과 저장 방식 비교

윈도우 공식 문서에 안내된 네 가지 핵심 복구·백업 도구의 특성을 비교하면 각 도구가 보호하는 영역이 명확하게 구분됩니다. 시스템 오류 해결용 기능과 문서 보존용 기능을 섞어 쓰지 않도록 기능을 사전에 분류해야 합니다.

| 도구 명칭 | 주 저장 위치 | 주요 보호 대상 | 버전 이력 관리 | 인터넷/계정 필수 여부 |
| :--- | :--- | :--- | :--- | :--- |
| **Windows Backup** | OneDrive (클라우드) | 지정 폴더, 앱 목록, Wi-Fi 정보, 윈도우 환경설정 | OneDrive 동기화 상태 기준 | 개인 MSA 및 클라우드 연결 필수 |
| **파일 기록 (File History)** | 외장 드라이브, 네트워크 위치 | 라이브러리(문서, 사진, 비디오, 음악), 바탕 화면 | 주기적 변경 이력 판본별 탐색 가능 | 외장 드라이브 또는 접근 가능한 네트워크 위치 필요 |
| **시스템 보호 (복원 지점)** | 시스템 드라이브 (내부 디스크) | 시스템 파일, 레지스트리, 설치된 프로그램 설정 | 복원 지점 생성 시점 기준 | 로컬 전용 (개인 파일 제외) |
| **복구 드라이브** | 전용 USB 드라이브 | 공장 초기화 파일, 시스템 빌드, 제조사 설정 | 단일 복구 이미지 (연 1회 재작성 권장) | 생성 도구가 요구하는 용량의 빈 USB (개인 파일 미포함) |

이 비교에서 확인할 수 있듯이 개인 문서 자체의 이력을 안전하게 남기려면 파일 기록이나 Windows Backup 폴더 동기화를 사용해야 합니다. 시스템 보호나 복구 드라이브는 윈도우 구동 환경 자체를 복구하는 도구이므로 개인 파일 백업을 대신하지 않습니다.

## 계정과 저장 장소에 따른 사전 점검 절차

어떤 백업 방식을 적용할지 결정하기 전에 사용 중인 윈도우 계정 유형과 연결된 저장 장치를 확인해야 합니다. 계정 형태에 따라 도구 실행 자체가 제한되거나 오류가 발생할 수 있습니다.

1. **마이크로소프트 계정(MSA) 확인**: 설정 앱의 계정 메뉴에서 현재 로그인된 상태를 확인합니다. Windows Backup 앱은 `@outlook.com`이나 `@live.com`과 같은 개인 마이크로소프트 계정으로 로그인한 환경을 중심으로 작동합니다. 로컬 계정을 사용 중이거나 조직 계정으로만 등록되어 있다면 앱을 통한 통합 백업이 제한될 수 있습니다.
2. **OneDrive 저장 공간 점검**: Windows Backup을 통해 바탕 화면, 문서, 사진, 비디오, 음악 폴더를 동기화하려는 경우 원드라이브의 남은 용량이 충분한지 살펴야 합니다. 용량이 부족하거나 원드라이브 로그인이 풀려 있으면 백업 진행 과정에서 오류가 발생하고 파일 동기화가 중단됩니다.
3. **파일 기록용 외장 드라이브 연결 상태 확인**: 파일 기록을 쓰려면 상시 연결하거나 정기적으로 연결할 수 있는 외장 하드 드라이브 또는 네트워크 공유 폴더가 준비되어 있어야 합니다. 백업 대상을 고를 때는 현재 파일이 있는 드라이브와 백업 저장 위치를 구분해 확인합니다.
4. **저장 위치와 대상 파일 확인**: 중요 파일을 지우거나 기존 드라이브를 포맷하며 시험하지 마세요. 연결한 장치 이름과 백업 대상 폴더를 확인한 뒤, 첫 백업 완료 여부를 살펴보는 순서가 안전합니다.

## Windows Backup 설정 방법과 복원 한계

Windows Backup은 새로운 윈도우 기기로 교체하거나 초기화 후 복귀할 때 작업 환경을 빠르게 재구성해 주는 유용한 도구입니다. 시작 메뉴 검색창에 백업을 입력하여 Windows Backup 앱을 열거나, 설정의 계정 항목 내 'Windows 백업' 메뉴에서 구성을 변경할 수 있습니다.

이 도구에서 다루는 범위는 다음과 같습니다:
- **폴더 동기화**: 바탕 화면, 문서, 사진, 비디오, 음악 폴더의 토글 스위치를 켜 원드라이브로 업로드합니다.
- **앱 목록 기억**: 설치된 앱의 목록을 프로필에 기록하여 새 기기에서 빠르게 설치 링크를 가져올 수 있습니다.
- **설정 및 환경설정**: 텍스트 크기, 투명도 효과, 마우스 포인터 스타일, 언어 및 국가 형식, 맞춤법 검사 사전, 창 맞춤(Snap Windows) 설정, 작업 표시줄 단추 결합 방식, Wi-Fi 네트워크 접속 정보, 자격 증명 정보를 클라우드에 저장합니다.

하지만 Windows Backup에는 명확한 한계가 있습니다. 설치된 프로그램의 모든 내부 데이터베이스와 파일까지 자동으로 포함된다고 생각해서는 안 됩니다. 공식 안내의 폴더 동기화 범위 밖에 둔 작업 파일은 별도로 보존할 경로를 정해야 합니다. 또한 클라우드 동기화 방식이므로 인터넷 접속이 불가능한 오프라인 단독 환경에서는 새 기기로 복원 작업을 수행할 수 없습니다. 따라서 대용량 동영상 편집 원본이나 특정 개발 프로젝트 폴더처럼 원드라이브 기본 경로 밖에 위치한 파일은 별도의 보존 절차가 필요합니다.

## 파일 기록(File History) 설정과 다른 위치 복원 순서

파일 기록은 파일이 수정될 때마다 주기적으로 변경 사항을 검사하여 외장 저장 장치에 판본을 남기는 기능입니다. 마이크로소프트 공식 안내에 따르면 문서, 사진, 비디오, 음악 등 기본 라이브러리와 바탕 화면이 자동으로 보호 대상에 포함됩니다.

### 파일 기록 구성 순서
1. 외장 드라이브를 컴퓨터에 연결하거나 네트워크 백업 위치를 지정합니다.
2. 제어판을 열고 '시스템 및 보안'에서 '파일 기록으로 파일의 백업 복사본 저장'을 선택합니다.
3. 대상 드라이브가 올바르게 인식되었는지 확인한 후 '켜기' 단추를 누릅니다. 다른 드라이브를 지정하려면 좌측의 '드라이브 선택' 메뉴를 이용합니다.
4. 기본 라이브러리 외에 다른 위치에 있는 폴더를 추가하려면, 파일 탐색기에서 해당 폴더를 마우스 오른쪽 단추로 누른 뒤 '추가 옵션 표시'에서 '라이브러리에 포함'을 선택합니다.

### 복원 및 덮어쓰기 방지 절차
파일이 손상되었거나 이전 내용이 필요할 때는 파일 탐색기에서 복원하고자 하는 파일이나 폴더의 상위 위치로 이동합니다. 폴더를 마우스 오른쪽 단추로 누르고 '이전 버전 복원'을 선택하면 나타나는 '이전 버전' 탭에서 백업 시점 목록을 확인할 수 있습니다.

여기서 즉시 '복원'을 누르면 컴퓨터에 있는 현재 파일이 백업본으로 완전히 대체되며, 이 대체 작업은 되돌릴 수 없습니다. 따라서 현재 작업 중인 파일의 최신 내용을 유지한 채 이전 기록을 대조하려면, 복원 단추 옆의 확장 메뉴를 눌러 **'다음으로 복원...(Restore to...)'**을 선택해 기존 파일과 다른 폴더 경로에 저장해야 안전합니다. 또한 라이브러리 바로가기 안에서 우클릭하지 말고 실제 저장된 원본 폴더 위치에서 '이전 버전 복원'을 실행해야 목록이 정상적으로 표시됩니다.

## 시스템 보호와 복구 드라이브가 개인 파일을 대체하지 못하는 이유

많은 사용자가 시스템 복원 지점을 만들어 두었거나 USB 복구 드라이브를 제작해 두면 개인 파일까지 모두 보호된다고 착각합니다. 하지만 공식 문서에 명시되어 있듯이 두 도구는 개인 데이터를 전혀 보존하지 않습니다.

- **시스템 보호(System Protection)**: `systempropertiesprotection.exe` 또는 제어판 복구 메뉴를 통해 켜는 이 기능은 시스템 파일, 레지스트리 키, 드라이버, 설치된 응용 프로그램의 상태만을 스냅샷으로 기록합니다. 드라이버 업데이트나 프로그램 충돌로 부팅이 불안정할 때 이전 복원 지점으로 되돌리는 데 유용하지만, 복원 지점을 적용하더라도 문서나 사진 같은 개인 파일은 변경되지 않으며 백업되지도 않습니다.
- **복구 드라이브(Recovery Drive)**: `recoverydrive.exe`로 생성하는 USB 복구 미디어는 하드 드라이브가 고장 나 완전히 교체(베어메탈 복구)해야 하는 상황에서 윈도우를 공장 초기 상태로 다시 설치하기 위한 도구입니다. PC 제조사의 사용자 지정 설정과 윈도우 핵심 시스템 파일만 포함되며, 개인 파일은 제작 과정에서 제외됩니다. 마이크로소프트 문서는 복구 미디어를 만들 때 비어 있는 USB를 사용해야 하며(기존 데이터 완전 삭제), 개인 파일 보존을 위해서는 반드시 Windows Backup이나 파일 기록 같은 별도 수단을 병행하라고 안내합니다.

## 사용자 환경별 도구 선택 기준

본인의 작업 환경과 저장 장치 보유 상황에 맞춰 올바른 백업 구성을 선택해야 불필요한 오류를 피할 수 있습니다.

| 사용자 상황 | 권장 도구 조합 | 선택 이유 및 주의점 |
| :--- | :--- | :--- |
| **노트북 1대로 클라우드 중심 작업을 하는 경우** | Windows Backup + OneDrive | 이동이 잦아 외장 드라이브 상시 연결이 어려우므로 설정과 주요 폴더를 클라우드로 실시간 동기화 |
| **단일 PC에서 문서·소스를 빈번히 수정하는 경우** | 파일 기록 (File History) | 실수로 내용을 지우거나 덮어썼을 때 이전 시점별 판본을 탐색기에서 즉시 대조·복원 가능 |
| **새 PC 구매 후 전체 환경을 이전하려는 경우** | Windows Backup | 초기 설정에서 같은 개인 계정으로 로그인하고 백업을 선택. 앱은 종류에 따라 다시 설치하며 지원되는 설정 범위 확인 |
| **드라이버 설치 및 시스템 튜닝을 자주 하는 경우** | 시스템 보호 (복원 지점) 활성화 | 레지스트리 및 드라이버 롤백을 지원하되, 개인 문서 백업은 파일 기록을 별도로 병행 |
| **디스크 고장 등 물리적 장애에 대비하려는 경우** | 복구 드라이브(USB) + 파일 기록(외장) | 복구 드라이브로 윈도우를 재설치한 뒤 외장 하드의 파일 기록으로 문서를 되돌리는 2단계 대응 |

## 흔히 저지르는 실수와 작업 중단 기준

백업과 복원 과정에서 발생하는 도구의 역할을 혼동하거나 저장 대상을 잘못 선택하면 백업 과정에서도 파일을 잃을 수 있습니다.

| 흔한 실수 유형 | 발생 가능한 문제 | 올바른 대처 및 중단 기준 |
| :--- | :--- | :--- |
| **복원 시 '복원' 단추 즉시 클릭** | 현재 작업 중인 최신 파일이 이전 판본으로 덮어써져 작업 내용 소실 | '다음으로 복원(Restore to...)'을 선택해 별도 폴더로 추출한 뒤 수동 대조 |
| **복구 드라이브를 개인 외장하드에 생성** | 복구 드라이브 생성 시 선택한 USB 드라이브에 있던 데이터가 삭제됨 | 중요 파일이 없는 빈 USB를 사용하고 도구에 표시되는 필요 용량과 선택한 장치 이름 확인 |
| **시스템 복원으로 삭제된 사진 복구 시도** | 시스템 복원은 개인 데이터에 관여하지 않으므로 삭제된 문서가 되돌아오지 않음 | 파일 기록의 '이전 버전 복원'이나 클라우드 휴지통을 통해 복원 진행 |
| **용량 부족 경고를 무시하고 방치** | OneDrive 용량이 초과되면 Windows Backup 동기화가 실패 상태로 멈춤 | 원드라이브 용량 초과 경고가 뜨면 먼저 어떤 파일이 동기화되지 않았는지 확인. 원본 위치와 별도 보존 경로를 확인하기 전에는 파일 삭제나 동기화 해제를 서두르지 않음 |
| **BitLocker 복구 키 미확인 상태 복원** | 복구 환경(Windows RE) 진입 시 암호화 키를 요구받아 작업 진행 불가 | 시스템 복원을 시작하기 전에 마이크로소프트 계정에서 BitLocker 복구 키 확인 |

## 자주 묻는 질문

### 외장 드라이브를 분리해 두면 파일 기록은 어떻게 되나요?
외장 드라이브가 연결되어 있지 않은 동안에는 파일 기록이 새 백업본을 외장 드라이브에 저장할 수 없습니다. 따라서 드라이브를 다시 연결할 때까지 해당 외장 장치에 새 판본이 저장됐다고 판단하면 안 됩니다. 드라이브를 다시 연결한 뒤 파일 기록 상태와 필요한 파일의 이전 버전 목록을 확인하세요. 주기적인 판본 보존이 필요하다면 정해진 시간마다 외장 장치를 연결해 주어야 합니다.

### 기본 라이브러리 밖의 작업 폴더도 파일 기록으로 보존할 수 있나요?
공식 안내는 다른 위치의 폴더를 기존 라이브러리에 넣거나 새 라이브러리를 만들어 포함하도록 설명합니다. 파일 탐색기에서 해당 폴더를 마우스 오른쪽 단추로 누르고 추가 옵션 표시, 라이브러리에 포함을 선택하세요. 경로를 설정한 것과 백업이 완료된 것은 다릅니다. 중요한 작업 폴더는 첫 백업 뒤 이전 버전 목록에서 내용을 확인하는 편이 안전합니다.

### Windows Backup으로 모든 응용 프로그램이 그대로 복구되나요?
그렇지 않습니다. Windows Backup의 '앱 기억' 기능은 마이크로소프트 스토어 및 등록된 응용 프로그램의 목록과 링크를 기억하는 방식입니다. 설치 파일과 프로그램 내부 설정 데이터 전체를 이미지 형태로 복제하는 것이 아니므로, 새 PC에서는 안내에 따라 앱을 다시 내려받아 설치하는 과정을 거치게 됩니다.

### 시스템 복원 지점을 적용하면 어제 작성한 워드 문서가 사라지나요?
사라지지 않습니다. 시스템 복원은 시스템 파일, 윈도우 레지스트리, 드라이버 및 설치된 소프트웨어 구성만 이전 시점으로 되돌립니다. 사용자가 작성한 문서, 사진, 이메일 등의 개인 데이터에는 영향을 주지 않으므로 문서 파일이 롤백되거나 지워지지 않습니다.

### 복구 드라이브는 한 번 만들어 두면 영구적으로 사용할 수 있나요?
마이크로소프트 공식 문서에서는 복구 드라이브를 매년(annually) 다시 생성할 것을 권장합니다. 윈도우 대규모 기능 업데이트와 보안 패치가 지속적으로 적용되므로, 제작 시점의 업데이트와 PC 제조사 설정이 복구 미디어에 들어갑니다. 최신 변경을 반영하려면 정기적으로 새로 만드는 편이 좋습니다. 공식 문서는 특정 보안 업데이트와 취소 정책이 적용된 장치에서 복구 드라이브가 영향을 받을 수 있다는 주의도 따로 안내합니다.

### 윈도우 10에서 파일 기록을 계속 사용해도 안전한가요?
공식 안내에 따르면 윈도우 10은 2025년 10월 14일에 무료 지원 및 보안 업데이트 제공이 종료되었습니다. 운영체제 자체는 그대로 실행할 수 있어 파일 기록 기능을 사용하더라도, 보안 지원이 중단된 환경에서는 잠재적인 보안 위험이 따르므로 마이크로소프트는 최신 윈도우 11 환경으로 전환할 것을 권장하고 있습니다.

## 실행 전 권장 확인 목록

실제 백업과 복원 작업을 시작하기 전에 아래 단계에 따라 환경을 점검하면 데이터 손실이나 복원 실패 위험을 크게 줄일 수 있습니다.

1. **계정 및 저장소 연결 상태 확인**: 시작 메뉴에서 설정을 열고 마이크로소프트 계정 정상 로그인 여부와 OneDrive 저장 공간 잔여 용량을 확인합니다.
2. **파일 기록용 외장 장치 배정**: 백업 전용으로 쓸 외장 드라이브를 PC에 연결하고, 제어판 파일 기록 메뉴에서 드라이브를 선택한 뒤 켬 상태로 전환합니다.
3. **시스템 보호 기능 활성화 점검**: `systempropertiesprotection.exe`를 실행하여 C 드라이브의 시스템 보호가 켜져 있는지 확인하고, 디스크 공간 사용 슬라이더를 적절히 조절합니다.
4. **덮어쓰기 방지 경로 확인**: 파일 기록을 통해 파일을 복원할 때는 즉시 '복원'을 누르지 말고 '다음으로 복원'을 선택하여 별도 임시 폴더에 내려받는 절차를 지킵니다.
